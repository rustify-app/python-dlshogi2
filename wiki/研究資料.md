# 研究資料

floodgate 4000 に向けた改善案の根拠です。数値は出典のもので、「推定」は出典の数値から計算した値、「未確認」は一次資料で確かめられなかった項目です。改善案と進み具合は「改善案」ページと Issue で管理します。

- 対象: r3（20b256 SE, dlshogi入力, YaneuraOu NNUE 9.00beta1 @10k nodes 教師 71.11M局面×2epoch）, RTX 2060（約5,400 nps 中盤）, Floodgate 3475 → 目標 4000

## 0. value 教師の定義

| 項目 | 内容 | 出典 |
|---|---|---|
| dlshogi公式 `train.py` の val_lambda の意味 | `loss = loss1 + (1-λ)*BCE(y, 勝敗t2) + λ*BCE(y, value)`。`value` は hcpe の `eval` を `score_to_value`（係数756）で勝率化したもの。**λ=1.0 は「評価値のみ」、λ=0 が「勝敗のみ」**。デフォルト 0.333 | https://github.com/TadaoYamaoka/DeepLearningShogi/blob/master/dlshogi/train.py , https://github.com/TadaoYamaoka/DeepLearningShogi/blob/master/cppshogi/python_module.cpp |
| 公式 `csa_to_hcpe.py` | `--filter_rating` デフォルト3500（両者）、評価値コメントの無い指し手はデフォルトで出力しない（`--out_noeval`で出力） | https://github.com/TadaoYamaoka/DeepLearningShogi/blob/master/dlshogi/utils/csa_to_hcpe.py |
| value accuracy の定義 | `binary_accuracy(y2, t2)`＝**勝敗に対する**一致率 | train.py（同上） |

- 確認済み: 当方の `pydlshogi2/features.py` `make_value_target` は `val_lambda` を**勝敗の重み**として扱う（公式と逆。1.0=勝敗のみ、当方デフォルト0.333=評価値寄り）。r4 は勝敗のみで学習していた
- 公式には評価値スケールを勝敗にロジスティック回帰で合わせる `--use_evalfix`（`curve_fit(score_to_value, eval, result)`）がある（data_loader.py: https://github.com/TadaoYamaoka/DeepLearningShogi/blob/master/dlshogi/data_loader.py ）

### 1.4 value 教師の混合
- dlshogi: 勝敗CE＋探索評価値CEの和（ブートストラップ）「経験的にブートストラップ手法は非ブートストラップ手法より性能が良い」（WCSC31/32 アピール 4.13/5.13）。公式デフォルト λ=0.333（train.py）
- 評価値→勝率の乖離は補正が必要（WCSC32 5.17）
- Lc0: 学習設定 `q_ratio` で `q*q_ratio + z*(1-q_ratio)` を value 教師にする（デフォルト0）: https://github.com/LeelaChessZero/lczero-training/blob/master/tf/tfprocess.py
- 当方: eval→winrate の手番符号バグで **λ<1 の過去実験は全て汚染**。「評価値混合は効かない」という結論は現時点で無根拠

### 1.5 ハード別モデルサイズ
- WCSC32 20b256 vs 電竜戦エキシ版 15b224（A100, 10秒）: NPS 43,990 vs 57,548（76.4%）、それでも R+143.8〜+182.6: https://tadaoyamaoka.hatenablog.com/entry/2022/06/20/210037
- 40b512 vs 30b384（H100, 400s+2s, 275局）: NPS 約0.54倍でも R+39.1±44.4: https://tadaoyamaoka.hatenablog.com/entry/2024/06/07/224348
- 50b640/60b768: 同一ノードでは強いが同一時間では弱い（H100）: 上記 2025/11/16 記事、WCSC35 アピール

## 2. r4 はなぜ「精度↑・棋力↓」になったか

### 2.1 同型の先行事例

| 事例 | 内容 | 出典 |
|---|---|---|
| AlphaGo Zero | SL は人間の手の予測精度が高いが、自己学習版の方が「much better overall」 | https://discovery.ucl.ac.uk/id/eprint/10045895/1/agz_unformatted_nature.pdf |
| AlphaGo (2016) | 探索内では SL 方策の方が強い RL 方策より良かった（予測精度・単体強さと探索内有用性は別） | https://storage.googleapis.com/deepmind-media/alphago/AlphaGoNaturePaper.pdf |
| AlphaGo value overfit | 完全な対局から勝敗を学ぶと局面相関で暗記: test MSE 0.37 vs train 0.19。1局1局面の3,000万局面で 0.226/0.234 | 同上 |
| dlshogi 方策分布学習 | Floodgate一致率は上がったが対局で弱化。原因は方策の性質変化で探索パラメータ不整合。Optuna再調整で解消 | WCSC32 アピール 5.15 |
| 同 定量 | 再調整前 3+1秒 432局で 46%（−27.6相当）、再調整後 1,024局で 49.8%（±10.5） | https://tadaoyamaoka.hatenablog.com/entry/2021/04/05/215431 |
| dlshogi 60b ファインチューニング | ファインチューニング後に弱化。「事前学習の分布からデータがずれた」可能性 | https://tadaoyamaoka.hatenablog.com/entry/2025/11/16/144404 |
| 破滅的忘却 | 逐次学習で旧タスク性能を失う。重要な重みの学習を遅くすると緩和（EWC） | https://arxiv.org/abs/1612.00796 |

### 2.2 r4 への当てはめ（仮説、要検証）
1. **評価分布のずれ**: test 精度は Floodgate 分布で測定＝学習と同分布。r3 の強さを決めていた分布（NNUE教師局面）上の精度・r3との対局で劣化していても見えない。→ r3 元テストセットでの精度も必ず併記
2. **勝敗のみ value は高分散・相関大**: 31M局面は1局あたり約100局面の強相関。AlphaGo の暗記事例と同型。1 epoch でも lr 0.02 は高い（下記）
3. **方策の性質変化と探索パラメータ不整合**: 教師が多エンジン人手混在の一手のみ（one-hot）。r3 の方策形状（NNUE 10k nodes 最善手）から変わり、Softmax_Temperature 等の最適点が動いた可能性（dlshogi 5.15 と同型）
4. **lr 0.02**: dlshogi 公式デフォルト lr=0.01（train.py）、RL は 0.01→0.001（WCSC30/31）。r3 の最終 lr から 0.02 へ戻すのは実質的な再学習で、忘却リスク大（EWC 論文の論点）。※ 最適 lr の一次資料での数値指定は**未確認**
5. **計測**: python MCTS 800 playouts・70局（±81）。本番は FukauraOu・時間制。dlshogi は同一時間/同一ノード両方で測る（上記各記事）

## 3. 固定の弱いGPUでのネットサイズ vs NPS

| 根拠 | 内容 | 出典 |
|---|---|---|
| dlshogi 時間倍化 | 1秒→8秒で +214.8 ≒ **+71.6/倍**（V100, 対水匠5）。過去測定 +84/倍 | https://tadaoyamaoka.hatenablog.com/entry/2022/02/09/212943 |
| dlshogi 15b224→20b256 | NPS 76.4%で +144〜183（ただし学習量も違う） | 2022/06/20 記事 |
| dlshogi 50b640 | NPS 約53%で同一時間弱化（H100） | WCSC35 アピール |
| KataGo | 後期の大型ネットは数百〜数千Elo強く、弱いハードでも動く限り小型を支配する見込み（評価は固定訪問数ベース） | https://github.com/lightvector/KataGo/blob/master/TrainingHistory.md |
| Lc0 | 「一般にハードで動く最大のネットを推奨」。Small=10b256 を弱いハード向けに掲載 | https://lczero.org/play/networks/bestnets/ |
| 実測 NPS（第三者） | 10b192: 3080Laptop 約33k / 3090 約58k、15b224: 約18k / 約32k（batch 128）。RTX 3060 15b: batch128 13–14k → 256 で 14–15k | https://zakkicho.cocolog-nifty.com/blog/2021/10/post-a33ee5.html |
| 当方 | 10b192→20b256 で約200 Elo 縮小（教師データ量も増加と同時） | 当方wiki |

- 推定: NPS 2倍 ≒ +72 なので、20b256→10b192（当方3090実測で約数倍のNPS）でも、同じデータで精度が落ちる分を補えるかは不明。当方実測では 20b256 の方が良かった
- 結論: **RTX 2060 で 20b256 は現状維持が妥当**。小型化は「20b256教師からの蒸留」を作れた場合のみ比較対象（dlshogi も 40b512→小型への蒸留を将来計画に記載: 2024/06/07 記事）
- 2060 での 15b224 等の Elo 実測は**未確認**（一次資料なし）。自前で同一時間 SPRT が必要
- 3475→4000 の差 525 は NPS だけでは埋まらない（推定: 4倍NPSでも +143〜168）。主因はモデル品質

## 5. 学習側テクニックの Elo 根拠

### 5.1 KataGo（Wu 2019, https://arxiv.org/abs/1902.10565 ）
- 全体: 同等手法比 約50倍の計算削減、30 GPU未満・19日で ELF 最終モデル超え
- 2日間アブレーション（2.5G 20b256相当クエリ時点、Table 2）

| 除去した要素 | Elo | 同Elo到達の学習時間倍率 |
|---|---|---|
| （本流） | 1329 | 1.00x |
| Playout Cap Randomization | 1242 | 1.37x |
| Forced Playouts + Policy Target Pruning | 1276 | 1.25x |
| Global Pooling | 1153 | 1.60x |
| 補助方策ターゲット | 1255 | 1.30x |
| 補助 ownership/score | 1139 | 1.65x |
| ゲーム固有特徴 | 1168 | 1.55x |

- PCR: 全探索 p=0.25、(N,n)=(600,100)→(1000,200)。全探索手のみ学習に記録
- いずれも**自己対局RLの効率化**手法。r3 のような NNUE 教師の教師あり学習には PCR/Forced playouts は直接適用できない
- global pooling は r3 の SE で部分的に代替済み（同等性は**未確認**）

### 5.2 Lc0
- WDL head: 2019年7月以降の全ネット。Elo 効果の記述なし: https://lczero.org/blog/2020/04/wdl-head/
- Moves-left head・SE: 学習設定に `moves_left`, `se_ratio` が存在（https://github.com/LeelaChessZero/lczero-training/blob/master/tf/configs/example.yaml ）。Elo 効果の一次資料は**未確認**
- Transformer(BT4): 生方策で T78(CNN) 比 +270 Elo、FLOPs 7.6G vs 12.45G。smolgen は「50%大きいモデル相当を throughput −10%で」: https://lczero.org/blog/2024/02/transformer-progress/ 。弱いGPU・TensorRT FP16 での効果は**未確認**
- dlshogi 側も ResNet＋Transformer、ラージカーネルへ移行（WCSC35）。ただし 2060 で FukauraOu が当該構造をどこまで高速に扱えるかは**未確認**

### 5.3 知識蒸留
- Hinton et al.: 大モデル/アンサンブルを小モデルへ: https://arxiv.org/abs/1503.02531
- dlshogi 20b→15b: α=0.5、温度なし、9,400万局面、lr 0.04 半減×4epoch。policy 47.83→48.87%、value 72.96→73.87%（4回平均）。**対局Eloは未報告**: https://tadaoyamaoka.hatenablog.com/entry/2022/06/19/151926
- 当方への含意: 「より強い/深い教師」の出力（方策分布＋評価値）を教師にすることは、dlshogi が NNUE 教師→RL→大モデル→蒸留と一貫して使う手法

### 5.4 教師の強さ・深さが上限
- r3 の教師は NNUE 10k nodes/局面。dlshogi は elmo 深さ8 事前学習を自己対局RLで超えた（WCSC31 4.8）
- dlshogi は深い探索でしか分からない局面に対し、水匠との評価値乖離局面を開始局面にして学習（2022/12/30 記事、定量値なし）
- 「NNUE 教師のノード数を増やすと r3 系がどれだけ強くなるか」の一次資料は**未確認**（自前測定が必要）
